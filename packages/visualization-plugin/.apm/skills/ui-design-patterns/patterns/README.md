# パターンの振り分け

## パターンのファイルの見出し

- 場面: どんなときか。
  2段落目に、その場面で何が困るかを書く
- 作り方: だからこうする、の中身
- 使わない場面: 似ているが、このパターンを当てない場面
- 根拠: 前例の出典の URL と、その前例が言っていること。
  原典を読めていないものは「二次」と書く
- 事例: 使って通った作り、差し戻された作り
- 確かめた回数: 「使って通った」の回数と、「前例」の件数。
  前例が無く、ユーザーの発言だけに拠るものは「前例: なし（ユーザーの発言だけに拠る）」と書く

## 共通の決まり

### 操作する画面は、縦スクロールの出ない1画面にできないかを先に考える

プレイヤー・ビューア・計算機のような操作する画面は、まず縦スクロールを出さずに1画面へ収める作りを考える。
文書・レポートのような読み物は対象外にする。
主な操作（再生など）は、親指が届く画面の下に置く。
いま要らない補助の操作は、最初から開いておかず、ボタンで開く形にする。
同時に見る必要のない説明（注意書き・値の出所など）は、別のページに分ける。

### 操作の説明を画面に書かない

見て触れば使い方がわかる形にする。
「左右にスワイプ」「欄から離れると保存」のような操作の案内文を足さない。

### 絵や記号で分かる所に文字を付けない

表示の文字を減らすと、表示の多言語対応が最小限で済む。
アイコン・絵・記号を見れば分かる所には、名前・見出し・状態・数値の文字を添えない。
例: アイコンのタブに名前を併記する、絵の候補の下に名前を付ける、「戻す」を文字のボタンにする、成功した保存を「保存しました」と出す、スライダーに項目名と数値を出す。
スライダーは、両端に最小・最大の値で描いた絵を置けば、項目名も数値も要らない。
文字は、失敗の知らせなど、絵では伝わらない所にだけ使う。

### 取り返しのつかない操作は、ふだんから危険と分かる色にする

全体を初期値に戻す・消す、のようなボタンは、押す前から赤系の色にする。
押した後の確認の状態とは、色の塗り方で区別する。

## 合わなかった案

ユーザーに差し戻された、または検討して捨てた作り。
同じ場面で再び出さない。

- 判断を求める画面の情報を、1画面に全部詰める: 収めるために理由や根拠を一文に削ることになる
- 区切りの無いカードを縦に並べて全部見せる: 何を見てほしいかが決まらない
- 初めて見る説明を結論から始める: 前提が無いまま結論を読むことになり、頭に入らない
- 出し直した2回目以降も状況から始める: 知っている前提を読み直させる
- 部品（差分・比較・図など）を毎回全部出す: 読めない。
  同じ部品が複数要る中身を1つに押し込むことになる
- 比べたいものを別のカードに分ける: 切り替えで違いを見落とす
- スマホの画面下に操作を何段も重ねる、大きな丸いボタンを置く: 内容の場所が減る
- 複数の操作を1つにまとめるボタンを、頼まれていないのに足す: 前に無かった操作が増え、何のボタンか分からない
- アイコンに絵文字や、意味が2通りに読める記号（↩ など）を使う: 見た目が簡素にならず、記号は意味を取り違える
