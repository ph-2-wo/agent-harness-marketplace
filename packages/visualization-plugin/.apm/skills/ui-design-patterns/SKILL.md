# UI Design Patterns

使って通った UI のパターンから、今の画面の場面に合うものを選ぶ。

数値データを図にする見せ方は、このスキルでは扱わない。
`data-viz-ideas` スキルを使う。

## 手順

1. 作り始める前に、その画面で使う人がいちばん見たいものを1つ決め、画面の主役にする。
   ボタンやリンクのような道具を、主役より目立たせない
2. `patterns/README.md` を読み、「場面」の列が今の画面に当たる行のパターンを選ぶ。
   複数当たれば組み合わせる。
   「合わなかった案」に当たる作りは選ばない。
   「共通の決まり」は、当たる行が無くても全部の画面に当てる
3. 選んだ `patterns/<name>.md` を読み、「使わない場面」に今の画面が当たらないことを確かめてから、「作り方」に従う
4. 当たる行が無く、作りのイメージが湧かなければ、似た用途のアプリやサービスの画面を探し、その構成に寄せてから作る。
   例: 道案内なら、地図アプリのナビ画面や乗換案内のルート詳細。
   寄せた前例の URL を控えておく
5. 作ったものをユーザーが差し戻さずに受け入れたら、次のどちらかをする
   - 表に無い作りが入っていた: `patterns/` に1ファイル足し、`patterns/README.md` の表に1行足す。
     見出しは既存のパターンにそろえ、「根拠」に手順4で控えた URL を書く
   - 既にあるパターンを使った: そのファイルの「確かめた回数」の「使って通った」を1つ増やし、「事例」に1行足す
6. ユーザーに差し戻された作りは、`patterns/README.md` の「合わなかった案」に理由と一緒に足す。
   既にあるパターンの作りが差し戻されたなら、そのパターンの「使わない場面」に今の場面を足す。
   差し戻しの言葉は、言われた範囲だけに当てる。
   例:「縦も横もスクロールがあるのはよくない」を「横スクロールは禁止」に広げない

5 と 6 は、この skill を配っている package の `.apm/skills/ui-design-patterns/` を直す。
展開先の `.claude/skills/` を直しても、次の `apm install` で消える。
