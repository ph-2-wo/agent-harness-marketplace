# harness-placement — 手順書をどこに置くか決める

## まず、ハーネスに書くものかを決める

- **指示**（これから毎回どう動くか） — ハーネスに置く
- **記録**（なぜそう決まったか、何が起きたか） — ハーネスの外の、作業の記録を置く場所に置く

指示に理由や経緯を添えない。無いと困ると分かった時点で足す。

## どこに置くか

|  | すべてのプロジェクト | チームの全員 | そのプロジェクト |
| :-- | :-- | :-- | :-- |
| **常に読まれるべきこと** | ユーザー全体に配る instruction | チームに配るパッケージの instruction | `<dir>/CLAUDE.md` |
| **常には読まないが、タスクをするのに役立つもの** | ユーザー全体に配るパッケージの skills | チームに配るパッケージの skills | `<dir>/.claude/skills/` |
| **強制力を持って特定のタイミングで作動させたい仕組み** | ユーザー全体に配るパッケージの hooks | チームに配るパッケージの hooks | `<dir>/.claude/settings.json` の hooks |

具体的にどのパッケージに当たるかは、チームの instruction に書く。

行（種類）を先に決め、次に列（スコープ）を決める。
要る場面を作業の名前で言えるもの（「Slack に投稿するとき」）は、大事でもスキルに置く。
スコープは「どのプロジェクトでも要るか、チームの全員に要るか、そのディレクトリの作業だけか」。

チームのスコープは、全員が同じパッケージを install するので全員に届く。

動く環境が限られるもの（特定のマシンでだけ動く hook など）は、その環境だけに配る置き場へ置く。

## 肥大化させない

3つとも、遵守させたいことを書く場所。**肥大化した時点で守られなくなる。**
instruction は毎ターン全文が読まれ、フックは条件が増えるほど判定が甘くなる。どちらも有限。

**入れたいものが増えたら、たいていスキルに分けるのが正解。**
