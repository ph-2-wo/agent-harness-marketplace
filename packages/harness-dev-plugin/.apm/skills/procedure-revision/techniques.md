# 手順を直すときの技術

## 1. 問題を受け取る

### 失敗の理由と範囲を決める

when

- 失敗や差し戻しの理由を決めようとしている

then

- 理由は見立てとして書き、確かめていないものは推測と書く
- 直す範囲は、その事例から言える範囲に収める。言えることが無ければ、直さない判断にする

### 指摘が複数ある

when

- 1つの成果物に、指摘やコメントが複数付いている

then

- 指摘の全体で何が実現できなかったかを見て、1つの問題にまとめる

## 2. 直す層と形を決める

### 前の直しの後で、また問題になった

when

- 前に直した所が、また問題になっている
- 前の直しの後に、別の問題が出ている

then

- 1つ上の層を直す層にする

### 例外を足そうとしている

when

- 既にある行に「ただし」「〜のときは除く」を足そうとしている

then

- 限定そのものを外すか、型を広げられないかを先に考える
- 足すものが既にある行と同じ類型に入るなら、類型を立てて並べ直す

事例

- 「話の途中は相槌だけにする」に「ただし、驚く短い問いを1回だけ挟んでよい」を足す案が差し戻された。通ったのは、話の途中に挟む形（相槌・短い驚き・中身を聞く問い・疑い）の一覧に並べ直した案だった

### 「〜しない」を足そうとしている

when

- 失敗した行動を、「〜しない」と書いて止めようとしている

then

- うまくいっている事例か成功のイメージを先に置き、そこへ向かう方法を書く

## 4. その層から組み直す

### 行を足す・書き換える

when

- 手順に行を足す・書き換える

then

- 語の1つずつに、記録か発言の根拠を持つ
- 「だけ」「〜まで」のような限定と回数は、他の形が無いと確かめたときだけ書く

### 前回・回数・日付を書きたくなる

when

- 「前回」「n回目」・日付・名前・記録への参照を、手順に書こうとしている

then

- 代わりに、そこから分かったことを手順の指示として書く

### 別の所を読ませる行

when

- 足す行が、手順を使う人に別のファイルや記録を読ませる

then

- 要る分を、その行の場所に書く

## 5. 失ったものと再現を確かめる

### 点検するか決める

when

- 再現の点検をするかを決める

then

- 考えれば分かることは、考えて決める
- 考えても分からないときだけ、手間の少ない点検を選ぶ

## 6. 周りを合わせる

### 同じことが複数の所にある

when

- 直したことと同じことが、他の手順や節にも書かれている

then

- 1か所にまとめ、残りを消す
