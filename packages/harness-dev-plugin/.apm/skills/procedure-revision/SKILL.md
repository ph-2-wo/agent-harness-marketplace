# 既にある手順を直す

工程ごとに当てる技術は `techniques.md` にある。
各工程で、その工程の `##` の下の技術を全部読み、when に当たるものの then を使う。

## 1. 問題を受け取る

終わったときにできているもの: 実現できなかったことと、それが起きた手順のステップの組。または、直さないという判断とその理由。

1. 受け取った失敗・指摘・学びを、手順で実現できなかったこととして言い直す
2. 手順を頭から辿り、それが起きたステップを決める
3. 直すかを決める。直さないなら、その理由を書く

## 2. 直す層と形を決める

終わったときにできているもの: 直す層と形と、その層を選んだ理由。

1. 1 のステップが、次のどの層にあるかを決める
   - 柱: 手順で何ができればよいか
   - 全体の構造: 工程の並びと、工程ごとの出口
   - 細かい構造: 工程の中の手順
   - 部品: 工程の中で当てる技術と、手順の詳細
2. 1 の実現できなかったことを、上の層が求めているかを見る。求めていなければ、上の層を直す層にする
3. 直す形を、追加・削除・分離と再構成・再設計から決める

## 3. 触る所の意図を読む

終わったときにできているもの: 触る範囲の行ごとの、入った理由の一覧。

1. 2 で決めた層から下で、触る範囲の行を挙げる
2. 行ごとに、git の履歴でその行が入った commit を探し、そのときの記録と合わせて、何のために入ったかを書く
   - 理由が見つからない行は、見つからないと書く

## 4. その層から組み直す

終わったときにできているもの: 削除か移動かが分かる差分。

1. 2 で決めた層を書き直し、その下の層を、書き直した層に合わせて組み直す
2. 足す行は、1 の問題から飛躍なく辿れるものだけにする
3. 消す行には消す理由を、移す行には移り先を付けて差分にする

## 5. 失ったものと再現を確かめる

終わったときにできているもの: 3 の一覧の各行が、差分の後でどこにあるかの対応。再現の点検をしたときは、その結果。

1. 3 の一覧の行ごとに、差分の後で残るか・移るか・消えるかを対応させる
   - 入った理由がまだ要るのに消えている行があれば、4 に戻る
2. 再現の点検をするかを決める
3. 点検するときは、想定の形を先に書き、差分の後の手順だけを渡したサブエージェントに同じ仕事をさせて比べる
   - ずれた所があれば、4 に戻る

## 6. 周りを合わせる

終わったときにできているもの: 同じことを書いた他の場所の一覧と、それぞれの差分。

1. 直した行の語と、直した手順のファイル名で、同じリポジトリの中を検索する。同じことを書いた所と、直した手順を説明・参照する所を挙げる
2. 食い違う所を直す差分を作る
3. 4 と 6 の差分を一式にして、承認を受ける
