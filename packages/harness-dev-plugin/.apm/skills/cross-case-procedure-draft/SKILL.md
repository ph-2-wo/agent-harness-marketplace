# 事例を横断して手順のラフを作る

試した事例を1つずつ評価し、全事例を横断して整理し、手順のラフを書く。
ラフの肉付けはこのスキルでは扱わない。

## 1. 使う事例を決める

## 2. 事例を1つずつウォークスルーする

1事例ずつ次をやり、全事例が終わるまで繰り返す。

1. その事例でやったことと、そこで得た学びを通して読む
2. やったことを順に1つずつ取り出し、事例の結果に照らして評価する
   - 評価は雑でよい。次の4つから選ぶ
     - 良い
     - 悪い
     - 良い所も悪い所もあった
     - あまり意味がなかった
3. 評価だけで伝わらない事情があれば、その行動に一言メモを付ける

## 3. 全事例を横断して整理する

1. 全事例でやっていた行動を、手順として洗い出す
   - 複数の事例に共通する行動は1つにまとめる
   - 1回しか出てこない行動も消さずに残す
2. 手順ごとに全事例の結果を並べて見て、2で雑につけた評価をつけ直す
   - 1事例だけでは見えなかったことを評価に入れる
   - 例えば、狙い通りだったのか偶然だったのか、行動そのものが悪かったのか使う場所が悪かっただけなのか
3. 事例には無いが、やると良さそう・悪そうと思いついたこともメモする

## 4. 手順のラフを書く

3で整理した手順を、次のように整えてラフにする。

- 実行する順に並べ替える
- 事例ではやっていたが、要らないものを外す
- 足りないものを足す
- 各手順は「〜する」の形で書く
  - 「〜しない」で書くのは、言い換えると意味が変わるときだけにする
- 別の手順を実行するときの条件になっているだけのもの（何を対象にしないか、どう仕上げるか など）は、独立した手順にせず、その手順の詳細にする
- 詳細は、書かないと忘れそうなものだけ書く

## 5. 報告する

`organized-explain` で次を説明する。

- 事例ごとの評価と、横断した整理の結果
- それに基づく手順のラフ

ラフが承認されたら、`procedure-draft-buildout` で具体的な手順にする。
