# 手順のラフを具体的な手順にする

手順のラフに事例や調査したことを肉付けし、大枠から順に具体化する。
肉付けの材料は、ラフの元になった事例と、足りない所を追加で調べたこととする。

## 1. 大枠を確かめる

ラフの工程の並びを、この後の段の土台として確定する。

## 2. 工程ごとの出口を決める

工程ごとに、終わったときにできているもの（次の工程に渡すもの）を決める。
それぞれに、事例や調査のどこから言えるかを理由として付ける。

全工程の出口を説明し、承認を受ける。

## 3. 工程の中の手順を決める

工程ごとに、中の手順を決める。
それぞれに、事例や調査のどこから言えるかを理由として付ける。
事例から分かったことは、事例への参照を残さず、手順の指示として書き込む。
手順の元にした事例や調査の記録を、手順を使うたびに読ませる手順は入れない。
工程が多いときは、工程ごとにサブエージェントに任せる。

全工程の中の手順を説明し、承認を受ける。

## 4. 各手順の詳細が必要な部分を決める

3で決めた手順のうち、詳細が必要な部分を決めて書く。
事例が大量にあり、手順に使える技術がたくさんあるときは、`custom-review` の構造を参考にまとめる。

## 5. 全体の構造を説明する

全体の構造を説明し、承認を受ける。
手順ファイルがリモートブランチに入っているなら、そのリンクを付ける。

## 選択肢を比べるとき

段の中で選択肢を比べるときは `repeating-diamond` を使う。
