# ブラウザで動くページの観点

## 動く環境

### スマホで使えない

when

- 見た目・操作の CSS や JS を書いている
  - レイアウト
  - 入力欄
  - タッチ操作
  - など
- など

then

- スマホの幅で操作できるかを確かめる。例:
  - 画面下に固定した要素が、本文やボタンを隠す
  - スワイプが縦スクロールとぶつかる
  - 画面の上端・下端に置いた要素が、iPhone の時計の帯・ホームバーにかかる。`viewport-fit=cover` なら上下の余白に `env(safe-area-inset-top/bottom)` を足す
  - 上端の要素が、iOS 26 の画面上端のぼかしにかかる。上の safe-area が 0 で渡る開き方もあるので、上には safe-area と別に固定の余白（約28px）も足す
  - grid・flex の列が、中の要素の最小幅に押されて画面より広がる。`overflow:hidden` で横スクロールが出ないと、右端のボタンやカードが切れて見える。grid の列は `minmax(0,1fr)` にし、flex の子には `min-width:0` を付ける
  - など
- Artifact のページは Claude アプリの枠の中に出るので、上下の帯とぼかしの例は当てない

事例

- 画面下に固定した通知が、ボタンを隠した
- 画面いっぱいに描く道案内のページで、上下の余白を 8px 固定にしていた。下のボタンがホームバーにくっつき、safe-area を足した後も、上の見出しが iOS 26 の上端のぼかしにかかって薄く見えた
- 1画面に収める grid のページで、列の幅を決めていなかった。iPhone でだけ列が画面より広がり、右上・右下のボタンとカードの右端が切れた。Chromium での確認では出なかった

### ログインの後ろのページで、ホーム画面のアイコンをファイルで指す

when

- `<link rel="apple-touch-icon">` を書いている
- そのページはログインの後ろにある

then

- 画像を data: URI で HTML に書き込ませる。ファイルを指すと、ホーム画面に追加するときの画像の取得がログインに回される

事例

- ログインの後ろの画面で、ホーム画面用のアイコンを同じホストのファイルで指した。iPhone でホーム画面に追加すると、アイコンが名前の頭文字になった。data: URI にしたら出た

### ホーム画面に追加して使うページで、manifest の scope を決めていない

when

- ホーム画面に追加して、アプリとして使うページを書いている
- 同じアプリの中で、パスの違うページへ移る

then

- manifest を置き、`scope` を移る先のパスが全部入る所（多くは `/`）にさせる。CSP が `default-src 'none'` なら `manifest-src 'self'` も足させる
- 開くたびに同じ入口から始めたいなら `start_url` も決めさせる。書かないと、追加したときのページを開く

事例

- セッションごとにパスの違う画面で manifest を置いていなかった。iPhone のホーム画面のアプリで別のセッションへ移ると、✕ と URL バーの付いたブラウザで開いた。パスの同じ切り替え（?scope=）では出なかった。scope を / にして足し直したら出なくなった

## 表示と操作

### 複数行の入力欄の高さが入力に合わせて変わらない

when

- `textarea` を置いている
- など

then

- 入力した行数に合わせて高さが伸びるかを確かめる。伸びないなら、入力のたびに高さを中身に合わせる処理を付けさせる
- 伸びる上限を決め、それを超えたら欄の中でスクロールさせる

事例

- コメント欄の高さが1行のままで、書いた内容が見えにくかった

### 表示の切り替えが効かない

when

- `hidden` 属性や `display` で表示を切り替えている
- など

then

- 同じ要素の `display` 指定で `hidden` が負けていないかを確かめる

事例

- `display: flex` の指定が `hidden` 属性を上書きし、隠したはずの要素が出ていた

### 操作を取り消せない

when

- 状態を変える操作を足す・消す
  - 完了
  - 削除
  - 判定
  - 捨てる
  - など
- など

then

- その操作を元に戻すボタンなどが、画面にあるかを確かめる。無ければ付けさせる
- 元に戻すための記録をメモリ上の変数にしか持っていないなら、ページを開き直しても戻せるよう、保存したデータから戻させる

事例

- 「戻す」を消して別の操作で代わりにしたが、元の用途を満たせなかった
- 完了を取り消せず、操作した場所から要素が消えた

### 1つの操作を、複数回の書き込みに分けている

when

- 1つの操作の中で、保存を2回以上呼んでいる
- 保存のたびに、保存先の写しで再描画している
- など

then

- 書き込みの間に、半分だけ変わった状態が画面に出ないかを確かめる
- 1回の書き込みにまとめるか、全部の書き込みが終わるまで描画しない形にさせる

事例

- カードの入れ替えが2回の書き込みに分かれ、途中の状態でカードが一度消えてから出た

### 補足が開いたまま並んでいる

when

- 答えの数字や主な操作の下に、補足を書いている
  - 計算の前提・推定の方法
  - 出典と注意
  - 数字の内訳の表
  - 選択肢のボタンの一覧
  - など
- など

then

- 最初の画面で答えを掴むのに要らない補足は `<details>` で畳み、最初は閉じておかせる
- 畳んだ見出し（`summary`）だけで中身が分かるようにさせる。選択肢のボタンを畳むなら、今の選択を見出しに1行で出させる
- 答え・主な操作・比較の一覧は畳まない

事例

- 計算のページで、幅の内訳と計算の前提が開いたまま並び、答えの数字が埋もれた
- 分布のページで、推定の方法・分位の表・出典・条件のボタンが開いたまま並び、答えの図が埋もれた

### アイコンに絵文字や文字の記号を使う

when

- ボタン・タブ・操作の段のアイコンに、次のものを置いている
  - 絵文字（✋ ✓ など）
  - 文字の記号（↩ ⋯ ▾ など）
  - など
- など

then

- 線の SVG アイコンに替えさせる
- 文字の記号を残すなら、その操作の意味にしか読めないかを確かめる。
  2通りに読めるなら替えさせる

事例

- 操作の段に絵文字のアイコンを置き、シンプルにするよう差し戻された
- 返事のボタンに ↩ を置いたが、改行・戻るにも読め、何のボタンか分からなかった

### アイコンに文字を併記する

when

- アイコンと同じ要素の中に、名前の文字を置いている
  - タブのアイコンの下の名前
  - アイコンのボタンの横の名前
  - など
- など

then

- アイコンを見れば分かるなら、文字を外させる
- 文字を残すのは、絵では伝わらない所（失敗の知らせなど）だけにさせる

事例

- 規則があるのに、アイコンのタブに名前を併記した見本を出し、差し戻された

### 画面下に操作を重ねる

when

- 画面下に固定した要素を、2段以上置いている
- 画面下の操作の段に、高さ 44px を超える要素（大きな丸いボタンなど）や余白を置いている
- など

then

- 1段にまとめ、高さを 44px 程度に抑えられないかを確かめる。
  重要度の低い操作はメニューに畳ませる

事例

- 画面下に3段置いた見本が差し戻された。
  1段にした後も、52px の丸いボタンと余白を残して、また差し戻された

### 縦書きの文字の折り返しを止めていない

when

- `writing-mode: vertical-rl` などで縦書きにした要素の、高さだけを制限している
- など

then

- 長い文字で、折り返して横に列が増えたときに、枠の幅を超えないかを確かめる
- 1列にするなら `white-space: nowrap` と `overflow: hidden` を付けさせる
- `text-overflow: ellipsis` は WebKit の縦書きで効かないことがある（https://bugs.webkit.org/show_bug.cgi?id=116413 ）。… が出なくても読めるかを確かめる

事例

- 細い枠に縦書きで出したラベルが、長いと高さの上限で折り返して2〜3列になり、枠の外へはみ出した

### 隠れる所に置いたカルーセルが、見えたときに位置を失う

when

- 横や縦に送るカルーセル・スライダーを、タブ・折りたたみ・シートのように `display:none` になる所に置いている
- 開く位置を指定している（startIndex など）か、送った位置を保ちたい
- など

then

- 隠れて幅が 0 になった間に位置が先頭へ潰れないか、隠れたまま作ったときに開く位置が効くかを確かめさせる。
  潰れるなら、幅がある間の位置を覚え、幅が戻ったときにそこへ戻させる
- 確かめるときは、本物の画面で、隠れる・見えるの順を作って位置を読ませる。
  部品だけを抜き出した試作では、画面が最初に別のタブで描かれてから切り替わる、のような順が再現しない

事例

- 横に送るカードの束を、開く位置を指定して作った。画面が最初に一方のタブで描かれ、すぐ別のタブへ切り替わるため、束は見えた状態で作られてから隠れ、隠れた間に位置が先頭へ潰れた。部品だけの試作で「隠れたまま作る」場合を直したが、本物の順では直らなかった
