# テストのコードの観点

## モック

### 外部との境界でない所をモックする

when

- テストで、モック・スタブ・差し替えを書いている
  - 本体の関数や、組み込みの関数（`Math` など）の上書き
  - 本体のソースの文字列置換
  - テストファイルの中に書いたモック
  - など
- など

then

- モックが、外部（API・db・ストレージなど）との境界だけに限られているかを確かめる。境界をどこにどう置くかは、リポジトリによる
- 外部との境界のモックが呼び出しの記録だけなら、保存したものを読み戻せる、状態を持つ fake にさせる
- 書き方の基準は `test-design` スキルの「外部との境界のモック・seed・helper を先に作る」

事例

- 保存先のモックがテストファイルごとにコピーされ、本体の関数まで上書きしていた。仕様を変えるたびに直す所が増えた

## seed

### 前のテストが作った状態を前提にする

when

- `describe` の外側の変数を、テストの中で代入している
- テストを順に走らせる指定をしている（`test.describe.serial` など）
- `beforeAll`・`beforeEach` の中で UI を操作している（`click`・`fill` など）
- など

then

- 各テストが、外部との境界のモックに入れた自分の seed から始まっているかを確かめる
- 書き方の基準は `test-design` スキルの「各テストは自分の seed から始める」

事例

- 後のテストが前のテストの作った状態に頼っていて、1つ直すと後ろが全部落ちた。1つだけ直したり、並べ替えたりできなかった

## wait

### 固定の wait を書く

when

- テストで、時間を決め打ちして待っている
  - `sleep`・`waitForTimeout`・`setTimeout` で待つ
  - helper の中の固定の待ち
  - など
- テストで、`setTimeout`・`Date` などの時間の関数を上書きしている
- など

then

- 状態になるまで待つ assertion か、テストの道具の fake timers に替えさせる
- 書き方の基準は `test-design` スキルの「固定の wait を書かない」

事例

- helper に固定の待ちが隠れていて、テストが極端に遅かった。待ちの大半は、状態を待てば要らなかった

## assert

### 実装の内部を assert する

when

- 呼び出し回数・呼び出しの引数・内部の変数・private な関数を assert している
- 組み込みの関数を包んで、呼ばれた回数を数えている
- など

then

- 出力と、ユーザーに見える状態の assert に替えさせる
- 保存の確認は、外部との境界のモックから読み戻した内容で行わせる
- 書き方の基準は `test-design` スキルの「assert するのは出力と見える状態だけ」

事例

- 計算の回数を数えるテストがあり、計算の仕方を変えるたびに落ちた

### 必ず通る assertion

when

- 値があることだけを見る assertion を書いている
- assertion を条件分岐の中に置いている
- 全件を確かめる assertion を書いている（`every`・`forEach`・`for` の中の assertion）
- エラーを握りつぶして先に進めている（`.catch(() => {})` など）
- など

then

- 仕様が壊れたときに、その assertion が落ちるかを確かめる
- 全件を確かめる assertion は、対象が空のときや、最初から条件を満たすデータのときに、何も確かめずに通らないかを確かめる
- 書き方の基準は `test-design` スキルの「必ず通る assertion を書かない」

事例

- 操作の失敗を握りつぶした後で状態を分岐していて、操作が失敗してもテストが通った
- 全件を確かめる assertion が、最初から条件を満たすデータで動いていて、必ず通った

### 期待値を緩める・実装の値に合わせる

when

- 既にある期待値を変えている
- 待つ時間・許す誤差を広げている
- など

then

- 変えた理由が、仕様の変更かを確かめる
- 仕様が変わっていないなら、元の強さに戻させる
- 書き方の基準は `test-design` スキルの「期待値は仕様から書く」

事例

- テストを書き直したとき、すぐ反映されることの確認が、待ち時間を数倍に緩めた形になっていた

## layer

### 同じ仕様を複数の場所で試す

when

- テストを足している（`test(`・`it(`・`describe(` など）
- など

then

- 同じ仕様を確かめるテストが、別のファイルや別の layer に既に無いかを探す
- あれば、1つの layer に寄せさせる
- 書き方の基準は `test-design` スキルの「仕様ごとに layer を決める」

事例

- 同じ見た目の確認が、いくつものテストファイルで重ねて書かれていた
