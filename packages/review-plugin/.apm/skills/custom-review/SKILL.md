# Custom Review

実際に起きた問題から蓄積した観点と、レビュー系のスキルを差分に当てる。
観点は `perspectives/` の観点ファイルにある。

## Workflow

### 1. 差分を決める

レビュー対象の差分を決める。
指定がなければ、作業中の commit していない変更とする。

### 2. 差分のファイルごとに観点を当てる

差分のファイル1つずつ、次を行う。

1. `perspectives/routing.md` に従って、観点ファイルとスキルを選ぶ（複数でもよい）
2. 差分のファイルが属する git リポジトリの直下に `review-perspectives.md` があれば、それも選ぶ
3. 選んだものを当てる。観点ファイルとスキルは互いに独立していて、順番は無い
   - 観点ファイル
     1. 差分の1行ずつ、各観点（`###` の見出し）の when に合致するか判定する
     2. 合致した観点の then を適用する
   - スキル
     - 差分のファイルに使う

`review-perspectives.md` の書式は `perspectives/` の観点ファイルと同じ（`##` のグループ、`###` の観点、when / then / 事例）。
作業場所の中に別のリポジトリが clone されていることがある。
そのため作業場所のリポジトリではなく、差分のファイルが属するリポジトリの直下で探す。
属するリポジトリの直下は `git -C <差分のファイルがあるディレクトリ> rev-parse --show-toplevel` で分かる。

観点の「事例」と「コード例」は、when の合致と then の当て方を示す few-shot として読む。

### 3. 指摘を返す

観点とスキルで見つかった問題を、指摘ごとに次の形で返す。

- 当たった観点（観点ファイルと見出し）かスキル
- 差分の行（ファイルと行）
- then かスキルに沿った指摘

指摘がなければその旨を返す。

## 観点を足す

実際に起きた問題を観点として足す。

1. 足す先の観点ファイルを選ぶ
   - when を、そのリポジトリの名前や固有のデータを出さずに書けるなら、共通の観点ファイルに足す。
     問題が起きたファイルを `perspectives/routing.md` に当てて選び、どれにも当たらなければ `general.md` にする
   - 書けないなら、問題が起きたファイルが属するリポジトリの直下の `review-perspectives.md` に足す。
     無ければ作る
2. 既にある観点の when に合致し、その then で防げた問題なら、その観点の「事例」に足す
3. 無ければ、当てはまる `##` のグループの下に `### 観点タイトル` を足し、when / then / 事例 を書く。当てはまるグループが無ければグループも足す。when は、差分の1行を見て判定できる条件で書く
4. 事例には、何が起きたかを書く。起きた場所（リポジトリ名・メンバー名）は書かない

共通の観点ファイルの正本は、この skill を配っている package の `.apm/skills/custom-review/perspectives/` にある。
展開先の `.claude/skills/` を直接直さない。
