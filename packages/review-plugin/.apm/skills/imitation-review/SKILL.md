# Imitation Review

## Workflow

### 1. どこの真似をしているかを明確にする

すでにわかってる場合はそのまま
わからない場合は、コードのどの箇所を真似しているかを明確にする調査をする

真似をする箇所は一箇所とは限らない
「この要素はこのファイルを、こちらは別のファイルを模倣する」などの可能性がある

### 2. 比較できる箇所は機械比較する

模倣元と対象の対応が明確な場合、目視判断の前に差分commandで比較できないか検討する

特に次は比較する価値が高い

- ファイル全体が別ファイルを模倣している
- 明示できる範囲が別の範囲からコピーされている

ファイル全体の例:

```sh
git diff --no-index -- path/to/source path/to/target
```

範囲比較の例（bash/zsh）:

```sh
diff -u \
  <(sed -n '10,40p' path/to/source) \
  <(sed -n '70,100p' path/to/target)
```

上記commandの終了値`1`は、実行失敗ではなく差分検出を示す

commandは例であり、同じ比較を決定論的に行える既存toolへ置き換えてよい

比較できない場合や差分noiseが判断材料にならない場合は、無理に使わず後続の判断へ進む

機械比較は指定の対応箇所の差分を示すだけであり、模倣元の妥当性や差分理由の判断は置き換えない

### 3-A. 真似をしている場合、真似をして問題ないかを考える

理由づけと判断をしていく
判断は100%ではつかないと思い、確率をつけて判断する

- 別の指示とのコンフリクトがある場合、どちらを優先すべきかの理由を明確にする
- 複数箇所の真似をする際、どちらを優先すべきかを理由づけする
- 役割から、真似ではなく共通部品にするべきものかを判断する

### 3-B. 真似をしていない場合、真似をしなくて問題ないかを考える

- 単に模倣元が見つからない場合もそれだけで答えとしない
- ex.「このテストは初めて書くので模倣元はないが、書き方は既存のこのテストファイル等を参考にするべき」
- 3-A のような理由の場合も、真似をしないことの方が優先されるのかを検討して理由づけと確率をつけて判断をする

### X. In Code Review

Plan Review の際は不要

- コメントアウト、改行、docstringも含めて模倣の観点とする

### 4. レビュー結果の返却

要素ごとに以下を返す

- 模倣元の箇所
- 模倣元のどの箇所を模倣しているか
- 模倣するべき/模倣しないべきの判断の確率と理由
- 機械比較をした場合、比較対象、使用command、残った差分
