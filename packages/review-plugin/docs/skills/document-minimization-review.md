# document-minimization-review

文章、Plan、instruction などの文書から、目的達成に必須でない記述をなくす観点でレビューする。

## 解決する課題

手順書や説明文は、書き足す方向にしか動かない。agent は「あった方が親切だろう」という理由で
条件・注意書き・言い換えを足し、人間も指摘のたびに1行を追加する。
どの行も単体では悪く見えないので、消す判断が起きないまま文書が肥大化する。

肥大化した文書は読まれない。読まれない手順書は守られないので、書き足した分だけ効果が下がる。

「消した方がいいか」で判断すると、この状態からは何も減らせない。書いた本人にとっては、
どの行にも書いた理由があるからである。

## 概要

- 対象範囲を決める（新規なら全体、改善なら改善箇所、掃除の指示なら全体）
- 全行について「消せる可能性があるか」だけを1行ずつ判定する。
  「消した方がいい」「消したら困る」では判定しない。迷った行は可能性がある側に倒す
- 可能性があると判定した箇所を全て消したベースラインを作る。
  ベースラインは文書として成立していなくてよい。成立させるための書き足しをここでしない
- ベースラインに無い記述を1つずつ、どうしても必要／悪くはない／どっちでもいい／悪影響 に分類する
- ベースラインへ「どうしても必要」だけを戻した本文を提案として返す。
  「悪くはない」は戻さず、別案としての並記だけを許可する

対象文書は編集しない。提案として返す。

## 利用場面

文書を新規作成した後、改善した後、または全体を掃除する指示を受けたとき。
`organized-explain`・`skill-review` から呼ばれるほか、単体でも使える。
