# imitation-review

既存実装をどこまで模倣できているかという観点でレビューする。

## 解決する課題

既存コードのあるリポジトリでは、新しい書き方を持ち込むこと自体がコストになる。
agent は一般論として正しいコードを書くが、周辺の書き方を読まずに書くと、
1 ファイルだけ規約が違う、テストの構成が既存と噛み合わない、といった差分が生まれる。

逆に、模倣すべきでない箇所まで機械的にコピーする問題もある。共通部品にすべきものを複製する、
別の指示と衝突しているのに模倣を優先する、といったケース。

## 概要

- どこを模倣しているかを特定する。模倣元は 1 箇所とは限らない
- 対応が明確な範囲は目視の前に差分コマンドで機械比較する
- 模倣している場合は「模倣してよいか」、していない場合は「しなくてよいか」を、
  100% ではなく確率を付けて理由づけする
- コードレビュー時はコメント・改行・docstring も観点に含める（Plan レビュー時は不要）

## 利用場面

Plan レビューとコードレビューの両方。単体で使う。

## 依存

なし。
