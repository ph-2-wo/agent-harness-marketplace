# WORKFLOW PLACEMENT

## 前提: 作業履歴

- 作成先はユーザーによるメモリ利用先の事前指示に従う

### タイミング

- 応答の前に履歴に保存する
- 作業開始前に前回の応答前に履歴に保存できてなかった場合は保存する

### プラクティス

- コードの概形が決まってる場合は言葉ではなくコードを書く方が確実性が高いので書く

## 1. 作業履歴を確認する

`instruction-management` によって最初の指示の管理を始める（以降返答があるたびに管理する）

メモリを読み、今どの段階にいるかを把握する

内容に基づき、以下のどこかに自分を配置する

### 調査

when

- やりたいことはまだ明確でなく、情報収集が必要な段階
- 調査を依頼された場合

then

- 調査を行う
- 結果は `zero` で説明する

### 要件策定

when

- 何ができるようになれば完了か（完了条件）に、ユーザーが合意した発言がまだない
- やりたいことはあるが、具体的にどんな方法を取るのか議論されていない
- 議論はされているが結論は出ていない

then

- 完了条件にユーザーが合意するまで `repeating-diamond`・`stepwise-system-design` などのスキルを使って進める

### 開発計画〜開発途中

when

- 完了条件をユーザー自身が述べた発言か、示した完了条件をユーザーが承認した発言を指せる段階
- あるいはなんらかの事情で開発途中の場合

then

- `flexible-dev` を使って開発を進める

### ユーザーレビュー

when

- 実装が完了し、ユーザーによるレビューを受ける段階

then

- レビュー依頼前の場合 `zero` を使って状況説明とレビュー依頼をする
