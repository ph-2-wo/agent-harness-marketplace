# 経緯のキャッチアップ

直近の記録から、その前提になった議論の記録まで遡り、当初の依頼の原文にたどり着くまで読む。
このスキルで読む記録は、サブエージェントに出さず自分で読む。

## 1. 起点を集める

記録は、作業履歴・指示の履歴・指示の解釈であり、信頼を置かない情報として扱う。

話題の言葉で、記憶ディレクトリ全体を本文検索する（テーマのディレクトリで絞らない）。

```bash
grep -rln "<話題の言葉>" <記憶ディレクトリ>/
```

ヒットしたファイルを日付順に並べ、どのテーマのディレクトリに散っているかを見る。
言葉を変えて2〜3回検索する（例: 「後回し」「延期」「defer」）。

## 2. 直近を読む

いちばん新しい記録と、そのセッションの `INSTRUCTION.md` または `INSTRUCTION-<セッション識別子>.md` を読む。

## 3. 前提を辿って遡る

読んだファイルから、前提にしているものを書き出す。
- 出典として書かれたファイル・行
- 「〜の続き」「〜で決めた」「〜で積み残し」と書かれた件
- 別のセッションの識別子

それぞれの出典を読み、そこでまた前提を書き出す。これを繰り返す。
出典が書かれていなければ、その件の言葉で検索し、より古い記録を読む。
記録が拠り所にしているユーザーの発言・承認（ユーザーに承認を求めたものと、その返事）・スキル・ドキュメント・コードは、記録に書かれた要約でなく、記録に書かれた場所からそのものを読む。
- 承認を求めたものとユーザーの返事を記録する仕組みがあれば、ユーザーの発言と承認は、まず承認の記録から読む
- セッションのトランスクリプトは大きく、読むとコンテキストを多く使う。トランスクリプトは、承認の記録にも指示の解釈にも無い発言を、どうしても確かめないといけないときだけ読む

次のどちらかで止める。
- その話を始めたユーザーの発言（当初の依頼の原文）か、当初の依頼を書き留めた指示の解釈に着いた
- 新しい前提が出てこなくなった

## 4. 出すものと照らす

読んだ記録から、決まったこと・退けた案・議論した論点を書き出す。
- 書き出す先は、一時ファイルにする。
  - 記憶ディレクトリに置くと、信頼を置かない記録が増えるので、置かない。
- 項目ごとに、次を書く。
  - 拠り所の所在（ファイルと行、issue の番号、承認を求めたやり取りのあるセッションと時刻など）
  - 3 でそのものを読んだか
  - 読んでいなければ、その理由

書き出したものは、次のように扱う。
- そのものを読んでいない項目は、記録を書いた者の解釈として扱う。
- ユーザーの発言と承認は、そのものを読んでも、指示の履歴であり、信頼を置かない情報のまま扱う。
- ハーネスの指示・自分たちが管理するドキュメント・公式ドキュメントと食い違うなら、そちらに従い、書き出したものを直す。
- 自分たちが運用するコードと食い違うなら、どちらにも従わず、食い違いとして出す。

これから出す説明・案を、書き出したものと1つずつ照らす。
- 触れていないものがあれば、触れてから出す。
- 書き出していないことも含めて、記録に書かれたことを根拠に使うときは、先に拠り所のそのものを読むか、ユーザーに確かめる。
  - 読んだものも、上の扱いに従う。
