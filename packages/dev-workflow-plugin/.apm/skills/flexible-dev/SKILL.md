# FLEXIBLE DEV WORKFLOW

## 0. Plan

`workflow-placement` の開発計画の when の1つ目（完了条件への合意の発言を指せる）に当たらないなら、実装に入らず要件策定に戻る

Planが決まっているならここは飛ばす

- 軽量な実装Planをする

### 0-2. 軽量 plan review once

- 事前に通すレビュースキルを実装方針を合わせるのに最適最小限に選定する
  - `imitation-review` は使用する
  - リポジトリのレビュースキルがあれば使う
  - ない場合はスキップ
- 問題があった場合一度だけ修正をする
- 2度目になった場合、 X. 方針再策定 に進む

## 1. 実装

Plan に従って実装する

## 1-2. 品質保証コマンド実行

テストやLinterやFormatterなど
リポジトリの品質保証に必要と案内されているコマンドを使用する
必要最小範囲に絞って実行する

特別にリポジトリ等で指示がある場合はその指示に従った範囲内で実行する

### 1-X. 実装失敗

1のどこかで Plan 通りに実現できなかった場合、ここに移動して対応方針を判定する

### 1-X-A. 軽微な修正による解決

when

- 軽微な修正で対応内容がコードレベルで明確にできている場合
- 修正が1度目の場合

then

- 軽微な修正を行う

### 1-X-B. 方針策定が必要

when

- 軽微な修正で対応できない場合
- 修正が複数回必要な場合

then

- X. 方針再策定 に進む

## 2. Self Review once

- review スキルを使う
  - claudeなら /code-review を使う
  - あわせて custom-review を使う
- リポジトリに固有のレビュースキルがあれば追加で使う
- その他ユーザー等のレビュースキルで利用該当するものを使用する

### 2-2. 修正方針策定

レビュー結果を元にこの後の方針を決める

### 2-2-A. 軽微な修正

when

- 指摘が全部で9個以内で、すべて修正方法が明確

then

- 軽微な修正を行って完成
- レビュー依頼に進む

### 2-2-B. 複雑な修正

when

- 指摘はあるものの修正方法の検討が必要なものがある
- 指摘が10個以上

then

- 止まるときは、全指摘を1回でまとめて出す
- 根本的な見直しのため X. 方針再策定 に進む

## 3. レビュー依頼

ユーザーへのレビュー依頼を `zero` を使って行う

### 3-2. レビュー結果対応

コミュニケーション上で進めて良い
時間がかかっている場合は X. 方針再策定 へ進むことを打診する

---

## X. 方針再策定

実装で見つかった問題に対処する手順
ここに該当したのが2度目の場合、X-X. ユーザー報告 に進む

### X-1. 課題の整理

起きている課題を整理する
`structured-refactor` スキルで情報を構造的に整理する

### X-2. 選択肢の選定

`repeating-diamond` を一度だけ実行し、選択肢をあげて整理する

### X-3. 継続判断

提出された選択肢からこのままエージェントのみで続けるかを判断する

#### X-3-A. エージェント継続

when

- 選択肢の中からどれを選べばいいかが明白
- その選択肢は何を変更すればいいかコードレベルで明確

then

- X に入る前にいた場所に戻る

#### X-3-B. 解決中断

when

- 選択肢の中からどれを選べばいいかが明白でない
- 選択肢は明白だが修正方法がコードレベルで明確でない

then

- X-X. ユーザー報告 に進む

### X-X. ユーザー報告

一旦エージェント単独での解決を諦めてユーザーに意見を求める
以下のスキルを使ってユーザーに状況を説明する

- `zero`
