# Instruction Management

## Independent file for instruction memo management

独立したファイルで指示メモを管理する

- 指示メモはトピックごとに持つ
- そのトピックの記憶ディレクトリに `INSTRUCTION.md` として置く（例 `memory/<テーマ>/INSTRUCTION.md`）
- 別のセッションで作った指示メモには追記せず、`INSTRUCTION-<セッション識別子>.md` として新しく作る
- ただし、ユーザーに前のセッションの続きだと明示されたときは、そのセッションの指示メモに追記してよい

以下の形式を取る

```
## 原文

## 解釈
```

このセクションは1つずつであり、指示のたびに原文や解釈セクションを増やしてはいけない
1つの原文セクション、1つの解釈セクションを管理し続けること

## Workflow

入力・返答があるたび、その回の作業を始める前に実行する

### 1. そのトピックの指示メモを開く

そのトピックの記憶ディレクトリの `INSTRUCTION.md` を見る

無ければ上の形式で新規作成する

### 2. その回の発言を反映する

編集は以下3パターン

- 追加指示をマージ
- 方針変更されたものを編集
- 解決済みのものをマーク

その回のユーザー発言は原文セクションに必ず入れる
入れるのは、原文からプライバシー情報と叱責を除去したものとする
除去だけを行い、原文への付け足しや書き換えはしない

追加の際は以下を守る

- 原文と解釈を分類可能なラベルをする

## Refactor

追加指示の反映完了後、指示管理文書をリファクタリングする

- ユーザー指示原文を見て、解釈セクションから以下のようなあなたが勝手に付け足したものを削ぎ落とす
  - ユーザー指示に根拠のない解釈
  - 要求されていない条件、制約
  - 過剰な指示の拡大解釈
- 残ったものを構造的に整理する `structured-refactor` を使う

### Manual Refactor

上は毎回の自動リファクタリングだが、以下の場合は手動でリファクタリングを開始する

- ユーザーに指示された場合
- 解釈が100行を超えた場合にユーザーに確認を取り、リファクタリングするよう指示された場合

この場合は通常の手順に加えて以下に従う

- 正本が消えるとよくないので、リファクタリングの完了まではバックアップを持つこと
- 成果物が問題ないかをユーザーに確認をして、問題なければリファクタリング完了とする
  - ここでバックアップを削除する
