# Instruction Management

## Independent file for instruction memo management

独立したファイルで指示メモを管理する

- 指示メモはトピックごとに持つ
- そのトピックの記憶ディレクトリに `INSTRUCTION.md` として置く（例 `memory/<テーマ>/INSTRUCTION.md`）
- 別のセッションで作った指示メモには追記せず、`INSTRUCTION-<セッション識別子>.md` として新しく作る
- ただし、ユーザーに前のセッションの続きだと明示されたときは、そのセッションの指示メモに追記してよい

以下の形式を取る

```
## 解釈
```

このセクションは1つであり、指示のたびに解釈セクションを増やしてはいけない
1つの解釈セクションを管理し続けること

ユーザー発言の原文は指示メモに写さない。原文はそのセッションのトランスクリプトにある

## Workflow

入力・返答があるたび、その回の作業を始める前に実行する

### 1. そのトピックの指示メモを開く

そのトピックの記憶ディレクトリの `INSTRUCTION.md` を見る

無ければ上の形式で新規作成する
新規作成したら、`workflow-placement` でそのトピックの現在地を決める

### 2. その回の発言を反映する

編集は以下3パターン

- 追加指示をマージ
- 方針変更されたものを編集
- 解決済みのものをマーク

解釈の各項目には、根拠にした発言の時刻を付ける
1つの項目が複数の発言に拠るなら、全部の時刻を付ける

### 3. 今回やることを解釈と照らす

解釈セクションを全部読み、今回やろうとしていることを照らす

- どれかの項目に反していないか（退けられた案、付けられた条件）
- どれかの項目を置き去りにしていないか（未解決のまま、受け皿が無い）

当たるものがあれば、やる前に直す

## Refactor

追加指示の反映完了後、指示管理文書をリファクタリングする

- 各項目の時刻の発言をトランスクリプトで読み、解釈セクションから以下のようなあなたが勝手に付け足したものを削ぎ落とす
  - 時刻の無い項目
  - ユーザー指示に根拠のない解釈
  - 要求されていない条件、制約
  - 過剰な指示の拡大解釈
- 残ったものを構造的に整理する `structured-refactor` を使う

### Manual Refactor

上は毎回の自動リファクタリングだが、以下の場合は手動でリファクタリングを開始する

- ユーザーに指示された場合
- 解釈が100行を超えた場合にユーザーに確認を取り、リファクタリングするよう指示された場合

この場合は通常の手順に加えて以下に従う

- 正本が消えるとよくないので、リファクタリングの完了まではバックアップを持つこと
- 成果物が問題ないかをユーザーに確認をして、問題なければリファクタリング完了とする
  - ここでバックアップを削除する
