# サブエージェントへの依頼文

サブエージェントが知っているのは、依頼文に書かれたことと、子が自分で読めるものだけ。
親の会話、親が読んだファイル、親が読み込んだ skill は見えない。

目的・範囲・決まったことは細かく書く。
手段は書かない。

手段を書くと、親が持たない子側の文脈（コード、skill の手順）と食い違い、子を誤った方へ導く。
子が自分で調べれば手に入るものは、中身を書かずに所在を指す。

## 書くこと

- 目的: 何のための仕事か、結果を何に使うか
- 範囲: やること、やらないこと、触らない場所
- 決まったこと: ユーザーの判断と、既に退けた案
  - 渡さないと、子は退けた案を出し直す
  - ユーザーの判断は原文のまま書き、親の解釈と分ける
  - 記録にあるなら本文を写さず、所在（ファイルのパス、issue の番号）を指す
  - 記録に無いものは、原文を書く
- 使う skill: 名前だけ書く
- 返す形: 何を、どの形で返してほしいか

## 書かないこと

- 手段: どのファイルをどの順に見るか、どのコマンドを打つか、成果物の文面をどう書くか
- skill・記録・コードにある手順や文面の書き写し: 名前と所在だけ書く
- 親の仮説・結論・解決の形
  - 渡すと、子は確かめて肯定して返しやすい
  - レビューや原因調査では、結論ではなくコードや症状を渡す

## 出す前に確かめる

- 目的と範囲を明確に書けるか
  - 書けないなら、親が仕事を理解できていない
  - 先に自分で調べる
- 子が親の `CLAUDE.md` を読むか
  - `Explore` と `Plan` など、読まない子がいる
  - そうした子に守らせたいルールは、依頼文に書く
- 会話全体を引き継がないと役に立たないほど背景が要る仕事か
  - そうなら依頼文に詰めず、会話を引き継ぐフォークで出す
