# 段階的なシステム設計

## 進め方

抽象、議論の基盤から始める。
一段階ずつ `repeating-diamond` を使う。
特に序盤は、手近な方法に飛びつかず、システム的に歪みがなく負債の少ない方法を選ぶ。

## 技術ごとのポイント

### プラットフォーム

その技術の一般的な利用方法かどうかが、負債を生まないポイント。
できれば公式ドキュメントを参照し、選定と説得の材料とする。

### DB スキーマ

コードの多くが依存するので、次を考える。

- これでやりたいことを満たせるか
- 将来の可能性にどの程度の制約を付けるか、それが問題ないか

### ユーザー体験

ユーザーが触る部分の設計は、ユーザー体験を考え、選定と説得の材料とする。
システム的に序盤に考えることもある（例: 認証の手間が大きくないか）。
