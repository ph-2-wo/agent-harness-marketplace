## 承認

- 以下の場合、承認の要否を次の判定で決める
  - 実装
  - 実行
    - 特にローカル以外に影響を与える行動の実行
- 上に当てはまる場合以下に従う
  - 上位目的、前提を明確にする
    - 「完了することで何ができるようになるか」を答える
  - その目的、前提についてユーザーと明示的合意をしていないなら承認必須
    - 手戻りの可能性がある

### 承認の判定

- 案・計画・変更案を出したら、**ユーザーが明示的に承認するまで実行しない**
- 承認とは「やって」「いいよ」「進めて」のような、**その案に対する許可の発話**を指す
  - 「良さそう」「それで」のように、案をそのまま受け入れる返事も承認に数える
  - 次のものは承認ではない——
    - **「〜したい」「〜すべき」「〜が要る」は意向**
    - **「出せ」「案を出せ」「基準を持て」は提出の指示**
    - **過去に別の件で出た許可**
    - **設計ページなど文書へのコメントでの同意（「良いです」）。案の中身への同意で、実行の許可ではない**
    - 案に疑問・指摘・反論が返ってきたら、それは**差し戻し**なので、実行しない
      - 指摘・反論には、案を直して再提出する
      - **疑問には、案を直す前に、根拠の原文（手順書・指示・ファイル）を読み直して答える**。自分のまとめや記憶で答えない

### 承認を求める事項は「ネクストアクション」と呼ぶ

- `create-next-action` に従って登録する

### 承認後に予定が失敗したとき

- **承認された予定が失敗したら、代わりの手を実行せず、止まって再計画し、承認を求め直す**
  - 承認されているのは提出した予定であって、それが崩れた後の代替手段ではない
