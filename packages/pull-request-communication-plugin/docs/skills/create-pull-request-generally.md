# create-pull-request-generally

リポジトリ固有の手順が無いときに、一般的な PR を作成する。

## 解決する課題

agent は PR 本文を差分から書くので、何を変えたかの羅列になり、なぜこの対応をするのかが抜ける。
レビューする側は、その方針が他の選択肢より良い理由を本文から読み取れない。

## 概要

- git log・差分などで自主的に情報を集め、判断できないことはユーザーに聞く
- リポジトリの `.github/pull_request_template.md` に沿って書く。無ければ skill 同梱のテンプレート（概要・アウトプット・備考・レビュー観点）を使う
- 理由は会話・コードベース・履歴から確かめ、git log やコミットだけから断定しない
- アウトプットには、差分から必要な動作確認項目を書く
- 本文をコードブロックで出し、ユーザーの OK を待ってから `gh pr create` で作る

## 利用場面

PR を作るとき。
リポジトリ固有の PR 作成 skill がある場合は使わない。

## 依存

`organized-explain`（`communication-plugin`）。
