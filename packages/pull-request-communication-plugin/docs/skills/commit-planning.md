# commit-planning

完成した実装を、変更理由と依存関係に基づく Commit へ分割する。

## 解決する課題

agent は作業が終わると全差分を 1 commit にまとめるか、逆にファイル単位・差分量単位で機械的に割る。
どちらもレビューできる単位にならない。commit の境界は、ファイルの境界ではなく変更理由の境界で決まる。

もう 1 つの問題は、分割の都合で実装を書き換えてしまうこと。
commit を綺麗にするために動作を変えるのは本末転倒なので、この skill では実装変更を禁じている。

## 概要

- 差分を型・独立した部品・既存機能の拡張・部品間の接続・test の観点で構造化し、各変更の理由と依存先を確認する
- 独立した変更理由を持ち単独でレビューできるものを分離候補、同じ目的で単独の価値がないものはまとめる
- 準備 commit を依存順に置き、最後に end-to-end で接続する
- 独立した目的のトピックが複数あれば PR 分割候補を出す（複数 commit であることは分割理由にしない）
- commit 列を提示して人間の合意を得てから作成する
- 分割のために実装変更が必要になったら停止して再合意する

branch 操作と PR 作成はこの skill では行わない。

## 利用場面

実装完了後、commit を切る前。計画だけの利用と、合意済み計画に従った commit 作成の両方に使う。

## 依存

なし。
