# Create Pull Request Generally

一般的な PR を作成する。

## Workflow

### 1. 情報収集

git log・差分などで、自主的に情報を集める。

判断できない場合は、ユーザーに質問する。

### 2. テンプレートの読み込み

`git rev-parse --show-toplevel` で取得したリポジトリルートの `.github/pull_request_template.md` を参照する。

存在しない場合は、この skill の [default-template.md](default-template.md) を使う。

### 3. 本文の作成

テンプレートに沿って、「本文の書き方」に従って本文を作成する。

### 4. 出力

本文をコードブロックで囲んで出力する。

### 5. 確認

ユーザーから OK が出たら、`gh pr create` で PR を作成する。

## 本文の書き方

### 理由

本文には、原則としてなぜこの対応をするのかを書く。

理由は、会話・コードベース・履歴・その他の周辺情報から確認する。
git log やコミットだけから理由を断定しない。

それでも判断できない場合は、ユーザーに確認する。
理由が不明なまま、変更内容だけの概要を作らない。

### 概要

概要セクションは `organized-explain` を使って作る。

### アウトプット

実施・未実施を問わず、差分から必要な動作確認項目を考えて書く。

例:

- このコンポーネントを変えたので、この動作を確認する
- API をこう叩いたときのレスポンスを確認する
- このライブラリのバージョンを上げたので、この部分の動作が壊れていないかを確認する

### その他

- 本文で別の PR を参照する場合は、前後に半角スペースを入れて ` #123 ` と書く
- テンプレートのうち、作成可能なところだけ作成する
- 対応の根拠となった情報ソースがあれば、必要な箇所に記載する
- 差分概要まとめのような羅列を書かない
- さまざまな選択肢からその方針を選んだ理由を、説得力を持って説明する
